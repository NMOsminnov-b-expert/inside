# ТЗ — Архив

Отдельная вкладка системы. Архив — это место, куда попадает всё, что человек
убрал из работы: документ, объект оценки, литера, учреждение, справочник.
Ничего из системы не исчезает безвозвратно: удаление в интерфейсе означает
«убрать с глаз и положить в архив», откуда запись можно найти, посмотреть и
вернуть на место.

Решения, принятые пользователем 03.09.2026 (не переоткрывать):

| Развилка | Решение |
|---|---|
| Что попадает в архив | **Документы со всех мест** (карточки ОЦ/ОИ, реестр «Документы», документы учреждений), **объекты оценки и литеры**, **учреждения** (с подведомственными), **справочники целиком** |
| Позиции справочников | В архив **не** пишутся: удаление позиции уже сопровождается заменой и записью в лог |
| Окончательное удаление | **Нет. Архив вечен** — ни у кого нет права стереть запись из архива, срока хранения тоже нет |
| Причина при отправке в архив | **Не требуется** — достаточно того, кто и когда убрал (это уже в записи и в логе) |
| Кто видит архив | Администратор и «любая роль» — весь; остальные — по своим учреждениям (то же правило, что у лога действий) |
| Кто возвращает из архива | **Администратор** и **сотрудник, закреплённый в том блоке, откуда запись убрали** — ОЦ, ОИ или учреждение (уточнение пользователя 03.09.2026). Остальные видят, но не возвращают |
| Удаление учреждения с объектами | **Каскад в архив**: узел, всё его поддерево и закреплённые за ними ОЦ уезжают в архив одной операцией; возврат поднимает всю ветку |
| Совпадение ЕНИ | Код **может повторяться** (уточнение пользователя 03.09.2026): совпавшие записи различаются **скрытым индексом**, человеку он не показывается. Поведение переключается флагом `ENI_UNIQUE` — чтобы макет настраивался одной строкой |
| Интерфейс | Просмотрщик содержимого в самом архиве, групповые действия по флажкам, группировка по объекту, столбцы как в реестрах (тянутся, переставляются, сортируются) |

### 1.1. Что сейчас удаляется безвозвратно

Каждая строка — точка в интерфейсе, где данные исчезают без следа. Это и есть
объём работ: после внедрения ТЗ все они должны вести в архив.

| Где | Функция | Что теряется |
|---|---|---|
| Реестр ОЦ, карточка ОЦ | `modules/*/data/store.js: removeRecord` | объект оценки целиком: литеры, документы, фото, заметки, особенности, лог |
| Перечень ОИ, карточка литеры | `modules/*/index.js` (удаление ОИ) | литера/помещение/участок со своими документами, фото, площадями |
| Реестр «Документы» | `kernel/documentsRegistry.js: removeDocument` | запись документа со всеми файлами и привязками к ОЦ |
| Карточка документа | `removeFile`, `removeLink` | отдельный файл документа; привязка документа к объекту |
| Документы учреждения | `pages/institutions: удаление документа` | то же, что в реестре — удаляет запись из реестра |
| Дерево учреждений | `kernel/institutions.js: removeNode` | учреждение (и поддерево при `withChildren`) со сотрудниками и регионом |
| Справочники | `kernel/dicts.js: removeDict` | справочник со всеми позициями и привязкой к полю |
| Просмотрщик документа | `parts/viewer/ctrl.js` (удаление страницы) | страница скана (в логе остаётся запись, самой страницы нет) |
| Карточка ОЦ | заметки, особенности, собственники, пользователи | строки списков; в лог пишется факт, содержимое не сохраняется |

Из этого списка в архив, по решению 03.09.2026, ведут первые семь. Страницы
скана, заметки, особенности, собственники и пользователи остаются как есть —
это части записи, а не самостоятельные объекты; их история уже в логе действий.

### 1.2. Чем текущая модель не годится под расширение

Архив лежит в самой записи ОЦ (`rec.archive`). Это работало, пока в архив
попадали только документы этой записи, и перестаёт работать сразу:

- **удалённый ОЦ некуда положить** — его архив исчез бы вместе с ним;
- **документ реестра и документ учреждения не принадлежат ни одному ОЦ** —
  у них нет `rec`, в котором можно хранить архивную запись;
- **учреждение и справочник** к ОЦ не относятся вовсе;
- **скрытый индекс ЕНИ и бронь кода** при `ENI_UNIQUE = true` (§6.3) требуют
  единого списка архивных записей, а не обхода живых.

Поэтому архив переносится в **собственное хранилище** — `kernel/archiveStore.js`
(§3), а `kernel/archive.js` остаётся набором операций над ним. Читатели
(`queryArchive`, `archiveFacets`) переезжают на новый источник, а старое поле
`rec.archive` мигрируется при первом чтении: записи переносятся в общий список
с `kind: 'document'`, поле удаляется.

## 2. Понятия

| Понятие | Значение |
|---|---|
| **Архивная запись** | Один факт «убрано из работы»: что убрано, откуда, кем, когда, и полный снимок содержимого, достаточный для возврата |
| **Вид записи** (`kind`) | `document`, `oc`, `oi`, `institution`, `dict` — от вида зависит, что записано в снимке и как выполняется возврат |
| **Источник** (`from`) | Место, откуда запись убрали: тип ОЦ, объект, литера, учреждение, каталог справочника. Нужен и для подписи в списке, и для возврата |
| **Снимок** (`payload`) | Данные записи на момент архивирования. Архив хранит не ссылку, а копию: объект, на который ссылались, к моменту возврата может не существовать |
| **Пакет** (`batch`) | Несколько записей, созданных одной операцией (каскад учреждения, удаление ОЦ с литерами). Возврат пакета возвращает всё вместе |
| **Возврат** | Восстановление записи на прежнее место. Если места больше нет — по правилам §5, но запись из архива не пропадает, пока возврат не удался |

## 3. Модель данных

### 3.1. Архивная запись

```js
{
  id: 'arc-17',                  // свой идентификатор архивной записи
  kind: 'document',              // document | oc | oi | institution | dict
  batchId: 'arcb-4',             // пакет: null, если запись одиночная
  batchRole: 'root' | 'child',   // корень пакета или его часть (для группировки в списке)

  title: 'Техпаспорт · skan.pdf',   // как называть запись в списке
  subtitle: 'Литера А · Администра…', // уточнение под названием

  archivedAt: '2026-09-03',      // дата (в макете — клиентская, см. §9)
  archivedBy: 'Осминов Н.',      // кто убрал
  restoredAt: null,              // дата возврата: заполняется при возврате
  restoredBy: null,              // кто вернул

  from: {
    place: 'oi',                 // oc | oi | docs | institution | dicts
    typeId: 'civil',             // тип ОЦ (для document/oc/oi)
    typeLabel: 'Гражданское здание',
    ocId: 'oc-cv-1',
    ocTitle: 'г. Бишкек, ул. Киевская, д. 218',
    eni: '147561671001',
    institution: 'Министерство …',   // учреждение объекта — по нему считаются права
    podved: 'Ошский филиал',
    oiId: 'oi-7',
    scopeLabel: 'Литера А · Административное здание',
    nodeId: 'inst-12',           // узел дерева (для institution)
    catalog: 'civil/building',   // каталог справочника (для dict)
    fieldKey: 'heating',         // поле, к которому был привязан справочник
  },

  payload: { /* снимок, состав зависит от kind — §4 */ },
}
```

**Инварианты записи:**

1. `payload` самодостаточен: возврат не обращается к живым данным за
   содержимым, только за местом, куда положить.
2. `from.institution` заполняется всегда, когда учреждение известно, — на нём
   держатся и видимость, и право возврата (§6).
3. Запись не изменяется после создания, кроме полей `restoredAt`/`restoredBy`.
   Возврат не удаляет запись из архива: архив вечен, и после возврата запись
   остаётся видна с пометкой «возвращено» (§7.6).
4. `id` архивной записи не совпадает с `id` содержимого: один и тот же документ
   мог уезжать в архив и возвращаться несколько раз, и каждый раз это отдельный
   факт.

### 3.2. Хранилище

`app/kernel/archiveStore.js` — плоский список записей плюс индексы:

| Функция | Назначение |
|---|---|
| `addEntries(entries)` | добавить записи (одним пакетом, если их несколько) |
| `allEntries()` | весь список (для запроса и фасетов) |
| `entryById(id)` | одна запись |
| `batchOf(batchId)` | все записи пакета в порядке добавления |
| `markRestored(id, who, when)` | пометить возвращённой |
| `eniTaken(eni)` | занят ли код ЕНИ архивной записью — нужно только при `ENI_UNIQUE = true` (§6.3) |
| `eniIndexes(eni)` | занятые скрытые индексы этого кода — чтобы возврат взял свободный (§6.3) |
| `nextArchiveId()` | идентификаторы `arc-N`, `arcb-N` |

Ядро по-прежнему не знает ни одного типа ОЦ: типы приходят из
`kernel/registry.js`, записи — из `records.js` модулей, ровно как сейчас.

## 4. Виды записей: что архивируется и как возвращается

Ниже — по каждому виду: чем вызывается, что уносит с собой, что происходит с
местом-источником, как выполняется возврат и какие крайние случаи учтены.

### 4.1. `document` — документ

**Откуда попадает:**

| Место | Действие в интерфейсе |
|---|---|
| Просмотрщик карточки ОЦ/ОИ | «В архив» (уже есть) |
| Реестр «Документы» | «Удалить» → в архив |
| Документы учреждения | «Удалить» → в архив (открепление ≠ архив, см. ниже) |
| Карточка документа | «Удалить документ» → в архив |

**Открепление и архивирование — разные вещи.** Открепить документ от
учреждения или от объекта значит снять связь: сам документ остаётся в реестре.
В архив уезжает только то, что человек удаляет.

**Снимок:** запись документа целиком — тип, номер, дата, статус, орган и дата
регистрации, принадлежность, владелец, учреждение, файлы (имя, mime, размер,
ссылка на содержимое), список привязок к объектам оценки, число страниц.

**Что с источником:** документ убирается из списка того места, откуда его
удалили; если он был в реестре — из реестра; связи с ОЦ/ОИ сохраняются в
снимке, чтобы возврат восстановил и их.

**Возврат:** документ возвращается в реестр и во все места, где был прикреплён.
Если объект оценки или литера, к которой он был привязан, больше не
существует — привязка не восстанавливается, документ возвращается в реестр, и
человек получает предупреждение с перечнем пропавших привязок. Если само
учреждение в архиве — документ возвращается в реестр без учреждения и
помечается «требует учреждения».

**Файл не освобождается** при архивировании: архивный документ открывают и
скачивают прямо из архива.

### 4.2. `oc` — объект оценки

**Откуда:** «Удалить объект» в карточке ОЦ и в реестре (групповое удаление —
пакетом).

**Снимок:** вся запись: реквизиты, ЕНИ, адрес, учреждение и подвед,
собственники и пользователи, ответственные по четырём ролям, статус, все ОИ со
своим содержимым (площади, развёртки, конструктив, фото, документы, заметки,
особенности), лог действий записи.

**Пакет:** одна архивная запись `kind:'oc'` (корень) плюс по одной записи
`kind:'document'` на каждый документ, который лежал в карточке, — чтобы
документ можно было найти в архиве поиском по имени файла, а не только внутри
объекта. Записи документов помечены `batchRole:'child'` и в списке по умолчанию
сложены под корневой (§7.4).

**Что с источником:** запись убирается из `records` модуля; реестр её больше не
показывает. Код ЕНИ и его скрытый индекс сохраняются в снимке; при
`ENI_UNIQUE = true` код уходит в бронь (§6.3).

**Возврат:** запись возвращается в свой модуль с тем же идентификатором и кодом
ЕНИ. Совпадение кода с живой записью возврату не мешает: возвращаемая запись
получает свободный скрытый индекс (§6.3).
Условия и крайние случаи:

| Случай | Поведение |
|---|---|
| Учреждение объекта существует | возврат как есть |
| Учреждение в архиве | объект возвращается **нераспределённым** (учреждение пустое), с пометкой в тосте; вернуть учреждение можно отдельно |
| Учреждение удалено окончательно | невозможно: архив вечен, окончательного удаления нет |
| Ответственные больше не работают | роли остаются заполненными снимком: это исторические данные, их правит человек |
| Документы объекта уже возвращены отдельно | не дублируются: возврат корня пропускает документы, у которых `restoredAt` заполнен |

### 4.3. `oi` — литера, помещение, участок

**Откуда:** «Удалить литеру» в карточке ОИ и крестик в перечне ОИ.

**Снимок:** объект имущества целиком: вид, литера, название, площади и
развёртка, конструктив, фото (счётчики по категориям), документы, заметки,
особенности, ссылки на связанные ОИ (например, квартиры в доме).

**Что с источником:** ОИ убирается из `rec.oi`; в лог записи пишется факт
(`pushOiDeletionLog` уже существует и остаётся); фотографии, которые по текущей
логике переносятся на ОЦ, переносятся как есть — снимок помнит, что было
перенесено, и возврат забирает их обратно.

**Возврат:** ОИ возвращается в свой ОЦ. Если ОЦ в архиве — сначала нужно вернуть
ОЦ: кнопка возврата у такой записи ведёт к корневой записи объекта и
подсказывает порядок. Если ОЦ вернули раньше — ОИ встаёт на место без вопросов.

### 4.4. `institution` — учреждение или подведомственная организация

**Откуда:** «Удалить» в карточке учреждения.

**Каскад (решение 03.09.2026):** одной операцией в архив уезжают:

1. сам узел;
2. всё его поддерево на любую глубину;
3. объекты оценки, закреплённые за узлами поддерева (`kind:'oc'`, пакетом);
4. документы этих объектов и документы самих учреждений.

Перед выполнением человек видит диалог с точным составом: «Уедет в архив:
1 учреждение, 4 подведомственных, 37 объектов оценки, 112 документов.
Вернуть можно целиком из архива». Никакой отмены после — только возврат.

**Снимок узла:** название, пояснение, регион, родитель, сотрудники по четырём
ролям, избранное, порядок в дереве.

**Возврат:** возвращает **всю ветку целиком** — узел, поддерево и объекты.
Крайние случаи:

| Случай | Поведение |
|---|---|
| Родитель узла тоже в архиве | ветка возвращается под ближайшего живого родителя; если живых нет — на верхний уровень, с пометкой |
| Родитель существует | ветка встаёт на прежнее место |
| Часть объектов уже вернули отдельно | они не дублируются (по `restoredAt`) |
| За время архива объект переподчинили другому учреждению | текущая привязка сильнее: объект остаётся там, где он сейчас, в отчёте о возврате это названо |

### 4.5. `dict` — справочник

**Откуда:** «Удалить справочник» в разделе «Справочники». Позиции справочника
в архив не пишутся (решение 03.09.2026).

**Снимок:** название, все позиции в своём порядке, привязка (тип ОЦ → тип ОИ →
поле), признак «системный», папка, связанные справочники.

**Что с источником:** справочник исчезает из каталога; поля, которые им
пользовались, переходят на встроенный перечень из кода — это то же поведение,
что и сегодня при удалении.

**Возврат:** справочник возвращается в свой каталог и снова привязывается к
полю. Крайние случаи:

| Случай | Поведение |
|---|---|
| Поле уже занято другим справочником | возврат предлагает замену (тот же диалог, что при переносе справочника между каталогами) — либо вернуть без привязки, «нераспределённым» |
| Каталога больше нет (тип ОИ убрали из системы) | справочник возвращается нераспределённым, с пометкой |
| В карточках уже накопились значения, которых нет в возвращаемом справочнике | значения остаются в записях: справочник ограничивает выбор, а не переписывает данные |

## 5. Правила возврата — общие

1. **Возврат идемпотентен**: повторное нажатие на уже возвращённую запись
   ничего не делает и говорит об этом.
2. **Возврат не молчит**: каждый возврат заканчивается сообщением, где сказано
   ровно то, что произошло, включая частичные случаи («документ возвращён в
   реестр, 2 привязки не восстановлены — объектов больше нет»).
3. **Возврат пакета** доступен на корневой записи и возвращает пакет целиком в
   порядке добавления (учреждение → подведы → объекты → документы).
4. **Возврат части пакета** разрешён: можно вернуть один документ из
   удалённого объекта, не поднимая сам объект, если объект существует. Если не
   существует — кнопка возврата у такой записи объясняет, что сначала нужен
   объект, и ведёт к его записи.
5. **Ничего не теряется при неудаче**: если возврат невозможен, запись остаётся
   в архиве в прежнем виде, `restoredAt` не заполняется.

## 6. Права

### 6.1. Видимость архива

| Роль | Что видит |
|---|---|
| Администратор, «любая роль» | весь архив |
| Оператор ЦОД, осмотрщик, оценщик, от учреждения | записи по своим учреждениям (`from.institution` ∈ `myInstitutions()`) |
| Сотрудник без учреждений | раздел недоступен (как сейчас, `canViewArchive`) |

Записи `kind:'dict'` не относятся ни к одному учреждению: их видят только
администратор и «любая роль».

### 6.2. Право возврата (уточнение пользователя 03.09.2026)

Возвращать может:

- **администратор** (и «любая роль» — по общему правилу проекта она равна
  администратору);
- **сотрудник, закреплённый в ТОМ БЛОКЕ, откуда запись убрали.** Неважно, что
  это за блок — объект оценки, объект имущества или учреждение: если человек
  стоит в составе сотрудников этой карточки, он может вернуть то, что из неё
  убрали.

Проверка идёт не по учреждению записи, а по составу сотрудников источника, и
это принципиально: у объекта и у учреждения свои составы, и человек, отвечающий
за литеру, не обязан отвечать за всё министерство.

| Вид записи | Чей состав сотрудников проверяется |
|---|---|
| `document`, убранный из карточки ОЦ | сотрудники этого ОЦ (`rec.resp`: `gov`, `cod`, `appr`, `insp`) |
| `document`, убранный из карточки ОИ | сотрудники ОИ, если состав задан у литеры; иначе — сотрудники её ОЦ |
| `document`, убранный из документов учреждения | сотрудники этого узла (`staffOf`, с наследованием от родителя) |
| `document`, убранный из реестра «Документы» | сотрудники учреждения, от которого документ (`doc.institution`) |
| `oc` | сотрудники самого объекта |
| `oi` | сотрудники ОИ, иначе его ОЦ |
| `institution` | сотрудники узла и всех его родителей (наследование состава уже работает в `kernel/institutions.js: staffOf`) |
| `dict` | только администратор: справочник — структура системы, состава сотрудников у него нет |

Наследование состава у учреждений учитывается: сотрудник министерства может
вернуть то, что убрали из подведомственной организации, если у той свой состав
не задан. Обратное неверно — сотрудник подведа не возвращает записи родителя.

Остальные видят запись и её содержимое, но кнопка возврата у них выключена с
подсказкой, кто может вернуть (§13).

Функция права живёт в одном месте — `kernel/archive.js: canRestore(entry)`, — и
её же использует экран, чтобы не расходились кнопка и действие.

### 6.3. Совпадение ЕНИ (уточнение пользователя 03.09.2026)

Код ЕНИ **может повторяться**: в практике встречаются объекты с одинаковым
кодом. Поэтому уникальность не является инвариантом системы, а совпавшие записи
различаются **скрытым индексом**.

| Что | Как |
|---|---|
| Скрытый индекс | внутреннее поле записи `eniIndex` (1, 2, 3…): у первой записи с этим кодом — 1, у следующей — 2 |
| Показ человеку | **никогда не показывается**: ни в реестре, ни в карточке, ни в архиве. Человек видит только сам код |
| Различение в интерфейсе | если в выборке несколько записей с одним кодом, они различаются адресом, учреждением и типом ОЦ — как и сегодня |
| Идентификаторы | внутренние `id` записей остаются уникальными: индекс нужен только для кода, а не для ссылок |
| Возврат из архива | **не блокируется совпадением кода**: возвращаемая запись получает свободный `eniIndex`, живые записи не трогаются |
| Поиск по коду | находит все записи с этим кодом; в архиве — тоже все |

**Флаг конфигурации.** Поведение переключается одной константой, чтобы макет
настраивался под решение заказчика без переписывания кода:

```js
// app/kernel/fmt.js (рядом с ENI_GROUPS / ENI_LENGTH)
//
// Могут ли коды ЕНИ повторяться. false — код уникален: система не даёт создать
// вторую запись с тем же кодом и держит бронь на коды архивных записей.
// true — совпадения допустимы, записи различаются скрытым eniIndex.
export const ENI_UNIQUE = false;
```

| Значение | Поведение системы |
|---|---|
| `ENI_UNIQUE = false` (по умолчанию) | совпадения допустимы; ввод того же кода проходит с предупреждением «такой код уже есть у N объектов» и списком ссылок; возврат из архива всегда возможен |
| `ENI_UNIQUE = true` | код уникален; форма создания не даёт сохранить дубль; архив держит бронь на коды своих записей (`archiveStore.eniTaken`), и в сообщении об ошибке появляется ссылка на архивную запись |

Флаг проверяется в трёх местах: `kernel/eniField.js` (ввод и проверка),
генераторы `nextEni`/`nextEniScoped` в модулях, возврат объекта из архива.
Больше нигде поведение от него зависеть не должно — иначе переключение
перестанет быть настройкой в одну строку.

## 7. Экран архива

Маршрут `#/archive`, пункт бокового меню «Архив».

### 7.1. Раскладка

Три зоны, по образцу учреждений и реестра документов:

```
┌────────────────────────────────────────────────────────────────────┐
│ Архив                    [поиск...]        [сброс]  Всего: 1 248  │
├──────────────┬─────────────────────────────────────────────────────┤
│  ФИЛЬТРЫ  ‹  │  [флажки: вернуть выбранное · выгрузить]            │
│              │ ┌─────────────────────────┬───────────────────────┐ │
│ Вид записи   │ │ таблица записей         │  СОДЕРЖИМОЕ       ‹   │ │
│ Тип документа│ │ (группировка по объекту)│  просмотрщик или      │ │
│ Тип ОЦ       │ │                         │  карточка записи      │ │
│ Учреждение   │ │                         │                       │ │
│ Кто убрал    │ │                         │                       │ │
│ Период       │ │                         │                       │ │
│ ☐ возвращённые│ │                        │                       │ │
└──────────────┴─┴─────────────────────────┴───────────────────────┴─┘
```

- Колонка фильтров сворачивается в вертикальную закладку (как фильтры сводной
  вкладки учреждений).
- Панель содержимого сворачивается перегородкой, ширина тянется и запоминается
  на время сессии — тот же приём, что в карточках ОЦ и в учреждениях.
- Ширины столбцов считаются от фактической ширины таблицы (`applyFit`), а не от
  суммы умолчаний.

### 7.2. Столбцы

Тянутся, переставляются, сортируются кликом по шапке; состав включается в меню
столбцов. По умолчанию показаны первые семь.

| Ключ | Подпись | По умолчанию | Сортировка |
|---|---|---|---|
| `kind` | Вид | да | по названию вида |
| `title` | Что убрано | да (тянущийся) | по алфавиту |
| `from` | Откуда | да | по объекту |
| `institution` | Учреждение | да | по алфавиту |
| `archivedBy` | Убрал | да | по алфавиту |
| `archivedAt` | Дата | да, сортировка по умолчанию (свежие сверху) | по дате |
| `act` | Действия | да, закреплённый | — |
| `docType` | Тип документа | нет | по алфавиту |
| `typeLabel` | Тип ОЦ | нет | по алфавиту |
| `eni` | ЕНИ | нет | по коду |
| `size` | Объём | нет | по числу |
| `restoredAt` | Возвращено | нет | по дате |

Вид записи показывается значком с подписью: 📄 документ, 🏢 объект оценки,
🅰 литера, 🏛 учреждение, 📚 справочник — чтобы вид читался, не считывая текст.

### 7.3. Фильтры

Фасеты со счётчиками, считаются по видимому набору без учёта самого фасета
(та же механика, что в реестре ОЦ и в сводной вкладке учреждений).

| Фильтр | Тип |
|---|---|
| Поиск | строка: название, тип, объект, ЕНИ, учреждение, кто убрал, имя файла |
| Вид записи | флажки: документ, объект оценки, литера, учреждение, справочник |
| Тип документа | флажки (только когда в наборе есть документы) |
| Тип ОЦ | флажки по пяти модулям |
| Учреждение | флажки с поиском внутри фасета |
| Кто убрал | флажки с поиском |
| Период «убрано» | две даты; пустая граница не ограничивает |
| Показывать возвращённые | флажок, по умолчанию **выключен**: возвращённые записи в списке не мешают |
| Только мои | флажок: записи, где я назначен на объект или закреплён за учреждением |

Выбранное показывается чипами над таблицей, у каждого чипа — крестик, рядом
«Сбросить всё». Состояние фильтров попадает в адрес (`#/archive?…`), чтобы
подборку можно было переслать коллеге — как в реестре ОЦ.

### 7.4. Группировка по объекту

Переключатель над таблицей: **плоский список** / **по объекту**.

В режиме «по объекту» строки собираются в группы по `from.ocId` (для записей
учреждений — по `from.nodeId`, для справочников — по каталогу). Шапка группы:
объект, ЕНИ, учреждение, число записей, дата последней. Группа сворачивается;
записи одного пакета внутри группы идут вместе, дочерние — с отступом под
корневой.

Свёрнутая группа показывает состав одной строкой: «1 объект оценки, 3 литеры,
12 документов».

### 7.5. Панель содержимого

Щёлкнули по строке — справа открывается содержимое, без ухода со страницы и без
открытия файла в новой вкладке (сегодня «Открыть» уводит в новую вкладку —
это уходит).

| Вид записи | Что в панели |
|---|---|
| Документ | просмотрщик `kernel/docViewer.js`: страницы, миниатюры, зум, поворот, колесо и горячие клавиши — как в учреждениях; ниже реквизиты документа |
| Объект оценки | карточка-снимок: реквизиты, состав ОИ, число документов и фото, ответственные, статус на момент архивирования |
| Литера | снимок литеры: вид, площади, развёртка, конструктив, документы |
| Учреждение | снимок узла: регион, сотрудники, состав поддерева, число объектов |
| Справочник | название, привязка, все позиции списком |

Панель одинаково устроена для всех видов: шапка с названием и датой, тело,
внизу — кнопка возврата (или объяснение, почему она недоступна).

### 7.6. Возвращённые записи

Возврат не удаляет запись: она остаётся в архиве и показывается приглушённо, с
подписью «возвращено 03.09.2026, Осминов Н.». По умолчанию такие записи
скрыты фильтром (§7.3). Так архив отвечает и на вопрос «что убирали и вернули»
— это история, а не только хранилище.

### 7.7. Групповые действия

Флажок в каждой строке и в шапке (выбрать всё видимое). При выборе появляется
полоса действий с числом выбранного:

| Действие | Поведение |
|---|---|
| Вернуть выбранное | последовательный возврат; в конце — отчёт: сколько вернулось, что не удалось и почему |
| Выгрузить список | CSV/XLSX по видимым столбцам выбранных записей (или всех, если ничего не выбрано) |
| Снять выделение | сбрасывает флажки |

Удаления из архива нет ни в одиночном, ни в групповом виде — архив вечен.

### 7.8. Пустые состояния

| Когда | Текст |
|---|---|
| Архив пуст вовсе | «В архиве пока ничего нет. Сюда попадает всё, что убирают из работы: документы, объекты оценки, литеры, учреждения, справочники. Ничего не удаляется безвозвратно.» |
| Пусто из-за фильтров | «Ничего не найдено. Снимите часть условий — счётчики у фильтров показывают, что останется.» |
| Нет доступа | раздел не показывается в меню (как сейчас) |

### 7.9. Счётчик в меню

Рядом с пунктом «Архив» — число записей, доступных этому сотруднику (без
возвращённых). Обновляется при архивировании и возврате.

## 8. Оформление интерфейса — требования и чек-лист

Раздел появился по требованию пользователя 03.09.2026: «сделай акцент на
оформление, с этим частенько проблемы — некоторые поля не докрасишь, стили
разойдутся». Ниже — правила, которые предотвращают именно те дефекты, которые
уже случались в проекте, и порядок приёмки экрана.

### 8.1. Ни одного собственного цвета и размера

| Правило | Почему |
|---|---|
| Цвета, радиусы, тени, размеры шрифта — **только через токены** `kernel/tokens.css` (`--blue-700`, `--line`, `--radius`, `--shadow`, `--muted`…). Никаких литералов `#hex` в стилях экрана | литерал живёт своей жизнью: при смене палитры он остаётся прежним, и блок выпадает из общей гаммы |
| Поле ввода, выпадающий список, кнопка, плашка-тег, значок состояния — **только общими классами** (`.input`, `.select`, `.btn`, `.tag-mini`, `.docs-status`, `.itag`) | ровно так «недокрашивалось» поле «Без движения»: страница задала ему высоту, но не рамку и фон, и его дорисовал браузер |
| Новый визуальный примитив заводится в `tokens.css`, а не в файле экрана | второй такой же примитив на другом экране обязательно разойдётся с первым |
| Локальные правила экрана задают **только раскладку**: место, отступы, ширины | всё остальное уже определено общими правилами |

### 8.2. Проверка «поле выглядит полем»

Перед сдачей экрана каждое поле ввода и каждый список проверяются по четырём
состояниям: обычное, наведение, фокус, отключённое. Для этого в отчёт идёт
снимок с раскрытым списком и с полем в фокусе, а не только общий вид экрана.

Дефекты, которые здесь ловятся (все встречались в проекте):

- поле без рамки и фона — стилизована только высота;
- нативный `<select>` вместо своего компонента (`kernel/dropdown.js`): свёрнутое
  поле выглядит своим, а раскрытый список рисует браузер;
- рамка есть, а `:focus` не подсвечен — непонятно, куда идёт ввод;
- отключённая кнопка не отличается от активной.

### 8.3. В интерфейсе нет кода — всё по-русски

Требование пользователя 03.09.2026: «все технические поля должны быть в
интерфейсе русифицированы, никаких кусков кода в интерфейсе».

| Что нельзя показывать | Что показывать вместо |
|---|---|
| Ключ поля (`regAuthority`, `staleDays`, `fieldKey`) | подпись поля: «Орган регистрации», «Без движения» |
| Идентификатор записи (`oc-cv-1`, `arc-17`, `inst-12`, `doc-4`) | название объекта, адрес, код ЕНИ — то, что человек узнаёт |
| Идентификатор типа ОЦ (`civil`, `land-plot`) | название типа: «Гражданское здание», «Земельный участок» |
| Значение вида записи (`kind: 'oi'`, `place: 'docs'`) | «Литера», «Реестр документов» |
| Служебные значения (`null`, `undefined`, `NaN`, `[object Object]`, `0000-00-00`) | прочерк «—» либо честная подпись «не указан», «дата не указана» |
| Английские подписи в шапках и кнопках | русские подписи |
| Технические сообщения об ошибках (текст исключения, стек) | человеческая формулировка: что случилось и что сделать |

**Где это чаще всего протекает** (проверять в первую очередь):

- подсказки `title` — их пишут в спешке и оставляют ключ поля;
- пустые значения: `${doc.regDate}` без запаса на пустоту печатает `undefined`;
- отладочные подписи в новых блоках, оставшиеся после разработки;
- выгрузка списка: в CSV уезжают ключи столбцов вместо подписей;
- сообщения об ошибках, собранные из технического текста.

**Правило для нового поля:** ключ и подпись задаются рядом, в одном месте
(как `ALL_COLUMNS` в `allObjects.js` или `fieldLabels.js` в логе действий), и
интерфейс берёт подпись только оттуда. Ключ без подписи — незаконченная работа.

Машинная проверка: на видимом тексте экрана не должно находиться ни
`undefined`, ни `null`, ни `NaN`, ни `[object`, ни идентификаторов вида
`oc-…`/`arc-…`/`inst-…`/`doc-…`, ни ключей латиницей в camelCase (§11).

### 8.4. Таблицы

| Правило | Дефект, который предотвращает |
|---|---|
| Ширины считаются от **фактической ширины таблицы** (`kernel/columns.js: applyFit` + `ResizeObserver`), а не от суммы умолчаний | таблица вылезает за экран или, наоборот, оставляет пустую полосу справа |
| Тянущийся столбец только один, у остальных заданы `width` и `minWidth` | резиновый столбец схлопывается в ноль и колонка пропадает совсем |
| `.ell` вешается на внутренний `<span>`, **никогда** на сам `<td>` | `display:block` снимает с ячейки `display:table-cell`, и ячейки складываются друг под другом |
| Плашки в ячейках (статус, тип) обрезаются многоточием, а не вылезают за колонку | длинный статус «Удостоверен после осмотра» перекрывает соседнюю колонку |
| Горизонтальная прокрутка — у своего контейнера, а не у страницы | страница уезжает вбок целиком |
| **Таблица не выходит за свой блок**: ширина таблицы равна ширине контейнера, ячейки не выступают за рамку, последняя колонка не обрезана рамкой | таблица «вылезает» из карточки — самая частая жалоба; случалось и в реестре документов, и в своде по подведомственным |
| Блок с таблицей не расширяется под содержимое: у контейнера `min-width: 0` (для flex-детей) и `overflow-x: auto` | ячейка с длинным текстом раздувает блок, и раскладку рвёт соседям |
| Столбец действий закреплён (`fixed`) и не участвует в подгонке ширин | кнопки уезжают за край или прижимаются к тексту |
| Сумма минимумов столбцов задаёт порог, ниже которого включается прокрутка, а не сжатие | столбцы ужимаются до нечитаемых «г. …» |

**Машинный критерий** (проверяется автопроверкой, §11): для каждой таблицы
экрана `table.scrollWidth <= container.clientWidth + 1` при обычной ширине окна,
и `container.scrollWidth === container.clientWidth` — то есть блок не
прокручивается сам и не раздут содержимым. Ни одна ячейка не выступает за
границы контейнера: `cell.right <= container.right + 1`.

### 8.5. Панели, перегородки, свёрнутые состояния

| Правило | Дефект |
|---|---|
| У свёрнутой панели всегда есть закладка для возврата | панель не вернуть, кроме перезагрузки |
| Пределы перегородки считаются от фактической ширины блока, а не константой | перегородка упирается задолго до края — «не даёт радикально менять размеры» |
| Ширина панели сохраняется между перерисовками | после любого действия раскладка сбрасывается |
| Повёрнутый текст: числа и значки внутри поворачиваются обратно | счётчик читается вверх ногами |
| Вложенная прокрутка ограничена по высоте (`min-height: 0` по всей цепочке flex) и имеет `overscroll-behavior: contain` | лента растёт во весь документ: колесо не прокручивает её, а содержимое обрезается |

### 8.6. Текст и переносы

| Правило | Дефект |
|---|---|
| Длинное название сокращается многоточием, полный текст — в подсказке (`kernel/overflowTip.js`) | заголовок переносится на вторую строку и сдвигает вниз весь экран |
| Подписи вкладок и кнопок — `white-space: nowrap` | «С подведомственными» рвётся на две строки, как только рядом появляется кнопка |
| Своя подсказка не дублирует видимый текст | подсказка всплывает поверх раскрытого списка и закрывает его первый пункт |
| Числа в столбцах — `font-variant-numeric: tabular-nums` | разряды не выстраиваются по вертикали |

### 8.7. Адаптивность мерить по блоку, а не по окну

Ширину задаёт перегородка, а не окно, поэтому пороги — **контейнерные запросы**
(`container-type: inline-size`), а не `@media`. Для архива это касается списка
записей (при узкой колонке строка перестраивается) и панели содержимого.

Проверяются три ширины: комфортная, узкая (≈270 px) и предельная (≈150 px). Ни
на одной из них не должно быть переполнения: `scrollWidth === clientWidth` у
строки — это и есть машинная проверка.

### 8.8. Порядок приёмки экрана

Ни один экран не считается готовым, пока не пройдены все четыре шага — по
правилам проекта из `CLAUDE.md`:

1. `python tools/checks/run.py` — все проверки зелёные; **ошибка в консоли
   браузера — автоматический провал**. В наборе есть сценарий
   `интерфейс без кода` (`check_ui_text.py`): он проверяет §8.3 и §8.4
   машинно — код в интерфейсе и таблицы, вышедшие за свой блок;
2. снимки через `tools/visual-parity/report.py` по каждому состоянию экрана:
   пустой архив, список, раскрытый фильтр, раскрытый выпадающий список,
   панель содержимого, свёрнутые панели, узкая колонка;
3. отдельный снимок каждого нового поля в фокусе и с раскрытым списком (§8.2);
4. `python tools/visual-parity/walk-new-build.py` — смоук по всем разделам:
   правки общих стилей задевают чужие экраны, и это проверяется, а не
   предполагается.

### 8.9. Частые ошибки, которые не должны повторяться

Список для ревью — по нему принимается работа:

**Оформление:**

- поле, список или кнопка отличаются от такого же элемента на другом экране;
- поле «недокрашено»: задана только высота, рамку и фон дорисовал браузер;
- цвет, радиус или тень заданы литералом, а не токеном;
- нативный `<select>` остался нативным;
- `:focus` не подсвечен, отключённое состояние не отличается от активного.

**Таблицы:**

- **таблица выходит за свой блок** — ячейки или последняя колонка за рамкой;
- таблица прокручивается по горизонтали там, где столбцы могли уместиться;
- столбец схлопнулся в ноль или вылез за рамку;
- блок раздут длинным содержимым ячейки (нет `min-width: 0`);
- `.ell` повешен на `<td>`, и ячейки сложились друг под другом.

**Текст:**

- **в интерфейсе виден код**: ключ поля, идентификатор записи, `civil` вместо
  «Гражданское здание»;
- `undefined`, `null`, `NaN`, `[object Object]` вместо прочерка;
- английская подпись в шапке, кнопке или подсказке;
- текст переносится там, где должен сокращаться;
- подсказка перекрывает то, что человек только что открыл.

**Раскладка и поведение:**

- панель свернулась и не возвращается;
- ширина панели сбрасывается после перерисовки;
- лента прокрутки не ограничена по высоте, колесо не работает;
- повёрнутый текст перевернул числа и значки;
- на узкой колонке содержимое переполняет строку;
- в консоли браузера есть хоть одна ошибка.

## 11. Автопроверки


Сценарий `tools/checks/check_archive.py` расширяется (сейчас 14 проверок).
Правила §8.3 и §8.4 уже вынесены в отдельный сценарий
`tools/checks/check_ui_text.py` (82 проверки): он проходит по всем экранам
макета и падает, если в интерфейсе оказался код или таблица вышла за свой
блок. Экран архива добавляется в его список `SCREENS` вместе с реализацией.
Каждая строка — дефект, который она обязана поймать. Сценарии §12 проходятся
целиком, а не только их отдельные шаги.

| Проверка | Какой дефект ловит |
|---|---|
| Документ из карточки ОЦ уезжает в архив и возвращается на то же место | регресс существующего поведения |
| Документ из реестра «Документы» уезжает в архив, а не исчезает | удаление минует архив |
| Документ учреждения: «удалить» → архив, «открепить» → остаётся в реестре | путаница открепления и архивирования |
| Удаление ОЦ: объект уходит из реестра, появляется в архиве, его документы — дочерними записями | потеря содержимого при удалении объекта |
| Возврат ОЦ: запись снова в реестре, ЕНИ и литеры на месте | неполный возврат |
| При `ENI_UNIQUE = false` возврат объекта с совпавшим кодом проходит, записи различаются скрытым индексом, человеку индекс не показан | возврат, заблокированный несуществующим правилом; утечка внутреннего индекса в интерфейс |
| При `ENI_UNIQUE = true` код архивного объекта нельзя занять новой записью, а ошибка ввода ведёт ссылкой в архив | флаг, который ничего не меняет |
| Удаление литеры: снимок уносит площади и документы, возврат ставит литеру назад | потеря данных литеры |
| Возврат литеры, когда её ОЦ в архиве: кнопка объясняет порядок и ведёт к объекту | «застрявшая» запись без пути возврата |
| Каскад учреждения: в архиве узел, поддерево и объекты одним пакетом; диалог называл верные числа | тихий каскад с неверным составом |
| Возврат ветки учреждения целиком: дерево и привязки объектов восстановлены | частичный возврат ветки |
| Возврат ветки, у которой родитель тоже в архиве: ветка встаёт под живого родителя | потеря узла при возврате |
| Справочник: удаление → архив, возврат → привязка к полю восстановлена | потеря привязки |
| Возврат справочника на занятое поле: предложена замена, ничего не перезаписано молча | молчаливая перезапись привязки |
| Права: сотрудник чужого учреждения не видит запись; сотрудник объекта видит и возвращает; чужой видит, но не возвращает | утечка и лишние права |
| Права по блоку-источнику: сотрудник литеры возвращает документ этой литеры; сотрудник министерства — документ подведа без своего состава; сотрудник подведа НЕ возвращает записи родителя | право, посчитанное по учреждению записи вместо состава блока (§6.2) |
| Кнопка возврата и само действие расходятся: действие вызвано в обход выключенной кнопки — отказ с тем же объяснением | право проверяется только в разметке |
| Возвращённые записи скрыты по умолчанию и показываются флажком с пометкой «возвращено» | архив как одноразовая корзина |
| Групповой возврат: отчёт по каждой записи, неудачные остались в архиве | молчаливая потеря при пакетном возврате |
| Просмотрщик в архиве: страницы, колесо, горячие клавиши, сворачивание панели | регресс просмотрщика вне карточек |
| Фасеты: счётчик фасета не учитывает сам фасет; сумма сходится с таблицей | фильтр, обнуляющий сам себя |
| Группировка по объекту: состав группы сходится с плоским списком | расхождение группировки и данных |
| Столбцы: тянутся, переставляются, сортируются; ширины считаются от фактической ширины | таблица, вылезающая за экран |
| (в `check_ui_text.py`) Текст: на экране нет `undefined`, `null`, `NaN`, `[object`, идентификаторов вида `oc-…`/`arc-…`/`inst-…`/`doc-…` и ключей латиницей в camelCase — ни в тексте, ни в подсказках `title` | код, протёкший в интерфейс (§8.3) |
| (в `check_ui_text.py`) Текст: все подписи столбцов, кнопок, фильтров и вкладок — по-русски | английская подпись, оставшаяся от разработки |
| (в `check_ui_text.py`) Таблицы: блок без прокрутки не раздут таблицей; при прокрутке вся таблица доступна прокруткой; страница не прокручивается по горизонтали | таблица, вышедшая за свой блок (§8.4) |
| Оформление: у каждого поля и списка на экране архива есть рамка, фон, подсветка фокуса и вид «отключено» | «недокрашенное» поле, дорисованное браузером (§8.2) |
| Оформление: нативных `select.select` на экране архива не осталось | раскрытый список, нарисованный браузером |
| Оформление: ни один столбец не схлопнут в ноль, таблица не переполняет контейнер, `.ell` висит на `<span>`, а не на `<td>` | сломанная раскладка таблицы (§8.4) |
| Оформление: на узкой колонке (270 px и 150 px) строка не переполняется — `scrollWidth === clientWidth` | верстка, посчитанная по окну вместо блока (§8.7) |
| Оформление: свёрнутые панели возвращаются закладкой, ширина сохраняется между перерисовками | панель без пути назад (§8.5) |
| Оформление: лента просмотрщика ограничена по высоте и прокручивается колесом, прокрутка не утекает на страницу | цепочка flex без `min-height: 0` (§8.5) |
| Ошибок в консоли нет ни на одном шаге | общее правило проекта |

## 12. Сценарии

Типовые задачи целиком, с точной последовательностью — по ним же строятся
автопроверки §14.

### 11.1. «Кто-то удалил техпаспорт, верните»

1. Оператор ЦОД открывает «Архив».
2. Вводит в поиск «техпаспорт киевская» — поиск идёт по названию, типу, объекту,
   ЕНИ, учреждению и имени файла, слова в любом порядке.
3. В списке видит запись: 📄 Техпаспорт · skan.pdf · Литера А · убрал Осминов Н.
   · 2026-09-03.
4. Щёлкает строку — справа открывается просмотрщик: страницы, миниатюры, зум.
   Убеждается, что это тот документ.
5. Нажимает «Вернуть». Тост: «Документ возвращён: Литера А · Административное
   здание».
6. Запись остаётся в архиве приглушённой с подписью «возвращено 03.09.2026».

### 11.2. «Объект удалили целиком»

1. Администратор открывает «Архив», в фильтре «Вид записи» выбирает
   «объект оценки».
2. Включает группировку «по объекту» — записи объекта собраны в одну группу:
   корневая запись объекта и 37 документов дочерними.
3. Открывает корневую запись: снимок карточки — реквизиты, ЕНИ, 4 литеры,
   ответственные, статус на момент удаления.
4. Нажимает «Вернуть всё». Отчёт: «Возвращено: объект оценки, 4 литеры,
   37 документов».
5. Открывает реестр — объект на месте, с тем же ЕНИ.

### 11.3. «Ликвидировали подведомственную организацию»

1. Администратор в учреждениях открывает узел и нажимает «Удалить».
2. Диалог: «Уедет в архив: 1 учреждение, 4 подведомственных, 37 объектов
   оценки, 112 документов. Вернуть можно целиком из архива.» — «В архив» /
   «Отмена».
3. Дерево обновляется: ветки нет; объекты из реестра исчезли.
4. Через неделю решение отменили: администратор находит в архиве запись
   🏛 учреждения и нажимает «Вернуть ветку».
5. Отчёт: «Возвращено: 5 учреждений, 37 объектов оценки. 2 объекта уже
   переподчинены другому учреждению — оставлены там, где сейчас.»

### 11.4. «Сотрудник видит, но не может вернуть»

1. Осмотрщик открывает «Архив» — видит только записи своих учреждений.
2. Находит документ по объекту, на который он назначен осмотрщиком: кнопка
   «Вернуть» активна.
3. Открывает документ по объекту, где он не назначен: кнопка выключена,
   подсказка — «Вернуть может администратор или сотрудник этого объекта».
4. Записи справочников он не видит вовсе.

### 11.5. «Проверка перед вводом нового объекта»

1. Оператор ЦОД создаёт объект и вводит ЕНИ, который уже был у удалённого.
2. При `ENI_UNIQUE = false` (по умолчанию) форма сохраняет запись, показав
   предупреждение «такой код уже есть у 1 объекта в архиве» со ссылкой: оператор
   решает сам — вернуть архивную запись или заводить новую.
3. При `ENI_UNIQUE = true` форма не даёт сохранить и предлагает ту же ссылку.
4. Оператор открывает запись, видит, что это тот же объект, и возвращает его
   вместо создания нового.

## 14. Крайние случаи — сводка

Одной таблицей, чтобы при реализации ничего не потерялось.

| Случай | Поведение |
|---|---|
| Возврат уже возвращённой записи | ничего не делает, тост «Эта запись уже возвращена» |
| Возврат документа, объект которого в архиве | документ возвращается в реестр без привязки, привязка называется в тосте |
| Возврат литеры, объект которой в архиве | запрещён, ведёт к записи объекта |
| Возврат объекта, учреждение которого в архиве | объект возвращается нераспределённым |
| Возврат ветки учреждения, родитель которой в архиве | ветка встаёт под ближайшего живого родителя, иначе на верхний уровень |
| Объект за время архива переподчинён | текущая привязка сильнее, расхождение названо в отчёте |
| Справочник возвращается на занятое поле | диалог замены либо возврат без привязки |
| Каталог справочника исчез | справочник возвращается нераспределённым |
| Документ был привязан к нескольким объектам, часть удалена | восстанавливаются существующие привязки, остальные перечислены в тосте |
| Файл документа недоступен (в макете — после перезагрузки вкладки) | запись видна, просмотрщик показывает «файл недоступен», возврат возможен |
| Архивная запись без учреждения (`from.institution` пусто) | видна только администратору и «любой роли» |
| Сотрудник потерял доступ к учреждению | записи этого учреждения перестают быть видны, но остаются в архиве |
| Групповой возврат, часть записей недоступна по правам | доступные возвращаются, недоступные перечислены в отчёте |
| Пакет, где часть записей уже возвращена | возвращается остаток, дубликатов не создаётся |
| Возврат объекта, чей код ЕНИ уже есть у живой записи | при `ENI_UNIQUE = false` возврат проходит, запись получает свободный скрытый индекс; при `true` — возврат запрещён со ссылкой на занявшую запись |
| Скрытый индекс просочился в интерфейс | считается дефектом: индекс не показывается ни в одном столбце, ни в подсказке, ни в выгрузке |
| Одновременный возврат одной записи из двух вкладок | в макете невозможно; на сервере — блокировка записи, см. §10 |

## 15. Производительность и клавиатура

| Требование | Решение |
|---|---|
| Объём архива растёт бесконечно (архив вечен) | список виртуализируется, как реестр ОЦ; фасеты считаются по индексам хранилища, а не полным обходом; страничная выборка на сервере |
| Поиск по мере набора | фильтрация на клиенте, пока записей меньше порога; выше — запрос с задержкой |
| Клавиатура | ↑/↓ — по строкам, Enter — открыть содержимое, Space — флажок, Esc — снять выделение; в просмотрщике — те же клавиши, что в карточках ОЦ (§7.5) |
| Фокус | после возврата фокус остаётся на следующей строке — чтобы можно было вернуть несколько записей подряд, не трогая мышь |

## 16. Этапы работ

Порядок такой, чтобы каждый этап заканчивался работающим состоянием.

| Этап | Содержание | Готовность |
|---|---|---|
| 1 | `kernel/archiveStore.js`, миграция `rec.archive` → общий список, `kind:'document'`; экран читает новый источник | архив работает как сейчас, но на новой модели |
| 2 | Документы со всех мест: реестр, учреждения, карточка документа | ни одно удаление документа не теряет данные |
| 3 | Объекты оценки и литеры: снимки, пакеты, возврат, скрытый индекс ЕНИ и флаг `ENI_UNIQUE` | удаление ОЦ и ОИ обратимо |
| 4 | Учреждения: каскад с диалогом состава, возврат ветки | удаление учреждения обратимо |
| 5 | Справочники: снимок и возврат привязки | удаление справочника обратимо |
| 6 | Экран: столбцы, фасеты, группировка, флажки, групповые действия, просмотрщик, возвращённые записи, счётчик в меню | архив как рабочий инструмент, а не список |
| 7 | Автопроверки §11, приёмка оформления §8.8, отчётные снимки, запись решений в граф знаний | сдача |

Демо-данные: в синтетику добавляются архивные записи всех пяти видов (сейчас
архив при старте пуст, и увидеть экран в работе можно только вручную удалив
что-нибудь).

## 17. На согласование

Пункты, которые в ТЗ решены по здравому смыслу и требуют подтверждения.

| Вопрос | Как решено сейчас в ТЗ |
|---|---|
| Возвращённые записи остаются в архиве навсегда и видны по флажку | да — «архив вечен» относится и к ним; это заодно даёт историю «убирали и вернули» |
| Литера, чей объект в архиве, возвращается только после объекта | да; альтернатива — возвращать литеру вместе с объектом автоматически |
| Объект возвращается нераспределённым, если его учреждение в архиве | да; альтернатива — требовать сначала вернуть учреждение |
| Ответственные в снимке не проверяются на актуальность | да — это исторические данные; альтернатива — очищать роли уволенных |
| Заметки, особенности, собственники, страницы сканов в архив не идут | да — это части записи, их история в логе |
| Выгрузка списка архива | CSV/XLSX по видимым столбцам; формат уточнить |
| Счётчик в меню считает записи без возвращённых | да; альтернатива — не показывать счётчик вовсе |
| Кто вправе видеть записи справочников | только администратор и «любая роль» |
| Значение флага `ENI_UNIQUE` по умолчанию | `false` — совпадения кодов допустимы, записи различаются скрытым индексом. Если по регламенту код всё-таки обязан быть уникальным, флаг переводится в `true` и поведение системы меняется по таблице §6.3 |
| Скрытый индекс ЕНИ нигде не показывается человеку | да — ни в столбцах, ни в подсказках, ни в выгрузке; различать записи с одним кодом человек будет по адресу, учреждению и типу ОЦ |
