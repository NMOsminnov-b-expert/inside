# ТЗ — Механизмы и оборудование

Новый, шестой тип объекта оценки (рядом с apartment/civil/production/
residential-house/land-plot). Ставится в один ряд с остальными в
«+ Создать ОЦ» (`app/kernel/registry.js`), но устроен иначе: у него нет ни
одного объекта имущества — сам объект оценки уже есть единица техники
(станок, экскаватор, генератор и т.п.), а не здание/участок с литерами
внутри.

Решения пользователя 07.09.2026 (не переоткрывать):

| Развилка | Решение |
|---|---|
| Модуль или подкатегория | **Самостоятельный тип ОЦ**, не расширение существующего модуля |
| Объекты имущества (ОИ) | **Нет** — сам ОЦ уже единица техники |
| Основные параметры | Без кода ЕНИ, без «назначения по ТП», без GPS-координат |
| Категория ОЦ | **Навсегда «Движимое»** — не выбирается пользователем |
| «02. Состав и тип имущества» | Заменяется **конструктором полей** (см. §2) |
| Старый ОИ «Механизмы и производственное оборудование» в production/civil (карточка `movable`, `kind:'МЕХ'`, фиксированные 3 поля) | **Заменяется** новой общей карточкой с конструктором полей — переиспользуется как ОИ в production/civil тем же приёмом, что и участок из land-plot |
| «Офисная техника и мебель» (второе значение того же `movable`) | Не трогаем, остаётся как было |

## 1. Основные параметры (карточка «01»)

Как у остальных модулей (Тип ОЦ, Статус ОЦ, Учреждение, Подвед, Адрес), но
**без** трёх полей, которые есть у пяти прежних модулей:

- код ЕНИ,
- назначение по ТП,
- GPS-координаты.

Категория ОЦ — как и везде, `<select disabled>`, но значение зафиксировано
модулем: «Движимое» (`app/modules/mechanisms/manifest.js: category`). Хук на
это уже существовал в `kernel/typeChange.js` (`changeOcType`) — записью
`taken.category = to.manifest.category`, просто им до сих пор не пользовался
ни один модуль.

## 2. Конструктор полей (карточка «02»)

Заменяет чекбокс «Имущественный комплекс» и раздел «Состав и тип имущества».
Модель данных записи — `rec.mech = { name, fields: [{id, label, value}] }`.

- **Название** — первая колонка, текстовое поле с историей (HTML `<datalist>`
  всех использованных ранее названий, `data/fieldTemplates.js: allNames()`).
  Можно вписать новое или выбрать использованное раньше.
- Набор полей всегда пересобирается под текущее название (уточнение
  пользователя 07.09.2026): выбрано **уже использовавшееся** название — под
  него подставляется набор полей (только подписи, без значений), который
  заводили для этого названия раньше (`getTemplate(name)`); название встречается
  **впервые** — поле полностью пустеет. Смена названия отменяет то, что было
  вписано в поля до неё, — это ожидаемое поведение, а не потеря данных.
- Кнопка «+ добавить поле» — пользователь сам придумывает подпись нового
  поля, поле добавляется к текущей записи и в шаблон этого названия
  (`rememberTemplate`) — при следующем выборе того же названия оно тоже
  подтянется.
- Значение поля — тоже с историей: у подписи поля есть своя история значений
  (`valueHistory` в `fieldTemplates.js`, датаlist на инпуте) — то есть каждое
  поле по смыслу и есть тот самый «словарь» на одно поле, только не
  кернел-овый (см. ниже).

### Почему не через `kernel/dicts.js`

Кернел-движок словарей строит список привязываемых полей (`allSlots()`)
только из статических `data/dictExport.js` каждого модуля — заранее описанных
пар (карточка, поле). Подпись поля здесь придумывает пользователь в рантайме,
привязать к ней справочник заранее нечем. Поэтому у конструктора свой,
локальный для модуля `mechanisms` механизм
(`app/modules/mechanisms/data/fieldTemplates.js`) — со своим ограничением:
**эти словари не видны и не редактируются на странице «Справочники»**. Если
это понадобится, потребуется отдельная доработка `kernel/dicts.js`
(поддержка динамических слотов) — сознательно не делалась в этой задаче.

## 3. Как ОИ внутри production и civil

В `production` и `civil` уже был вид ОИ с тем же человеческим названием —
«Механизмы и производственное оборудование» (карточка `movable`,
`kind:'МЕХ'`, фиксированные поля Наименование/Год/Заводской номер), включаемый
чекбоксом «Имущественный комплекс», продублированный копипастой в обоих
модулях. По решению пользователя он заменён общей карточкой
`app/modules/mechanisms/oi/mech/*` — переиспользуется production и civil тем
же приёмом, что и карточка земельного участка из `land-plot/oi/land/*`
(тонкий прокси-`index.js` в каждом потребителе, прямой импорт фабрики
`createMechOi` в `card/ocCard.ctrl.js`, запись в `oi/registry.js` и
`data/rules.js`). Это второе, наряду с land, осознанное исключение из правила
«`modules/* → modules/*` нельзя» (см. CLAUDE.md).

«Офисная техника и мебель» (второе значение того же `movable`) не тронута —
у неё остались фиксированные поля и мастер создания «монолит/комплекс».

Существующие сид-записи с `card:'movable', kind:'МЕХ'` мигрированы на новую
карточку: код ЕНИ, год выпуска и заводской номер стали полями конструктора
(данные не потеряны). У записи-«комплекса» (с вложенными узлами) новой модели
вложенного списка нет — каждый бывший узел стал отдельной единицей ОИ со
своими полями «Тип»/«Код ЕНИ».
