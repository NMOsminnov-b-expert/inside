# Промпт формирования ТЗ

Рабочая инструкция исполнителю. В сам документ ТЗ ничего из этого файла не
переносится.

---

## 1. Что описывает документ

Объекты учёта и сведения о них. Изложение идёт от объекта оценки к объектам
имущества, а не от устройства программы.

Собранные факты, на которых строится документ (граф знаний, 15.09.2026):

| Факт | Значение |
|---|---|
| Граница одной записи объекта оценки | один код ЕНИ |
| Тип записи | определяется главным объектом имущества |
| Главный объект имущества | наибольшая площадь или стоимость |
| Смена типа записи | вручную, когда состав изменился |
| Кто создаёт запись | ЦОД, оценка, администратор |
| Роли в макете | оператор ЦОД, осмотрщик, оценщик, ответственный от учреждения, администратор |
| Этапы | создание карточки, сбор документов, осмотр, дозаполнение после осмотра, оценка |
| Сбор документов и осмотр | не обязательны: решение пользователя и полнота документов |
| Заполняется дважды | конструктив и материалы, износ и состояние, инженерные сети и благоустройство |

## 2. Состав разделов

### Раздел 1. Объекты учёта

Для объекта оценки:

* признак, по которому сведения ведутся одной записью;
* что определяет тип записи и может ли тип измениться;
* перечень типов записи;
* какие виды объектов имущества допустимы в каждом типе, с номером пункта
  в меню создания;
* перечень блоков карточки в порядке экрана, с номерами.

Для каждого вида объекта имущества:

* признак, по которому объект заводят отдельной карточкой, и отличие от
  соседнего вида;
* типы записи, где вид доступен;
* перечень блоков карточки в порядке экрана, с номерами;
* поля, без которых карточка не сохраняется;
* поля, появляющиеся только при определённом значении другого поля — с
  указанием, какого именно значения.

### Раздел 2. Этапы

Пять этапов: создание карточки, сбор документов, осмотр, дозаполнение после
осмотра, оценка.

Для каждого этапа:

* какие роли на нём работают;
* какие блоки карточки заполняются;
* что известно об условии перехода к следующему этапу.

Отдельно перечисляются три группы сведений, заполняемые дважды:
предварительно по документам и точно после осмотра.

### Раздел 3. Правила и расчёты

Для каждого правила:

* что считается или проверяется;
* из каких полей берутся исходные величины;
* что происходит при расхождении: запрет, предупреждение или пометка.

Правила, уже действующие в макете: распределение площади по этажам между
отмеченными строками, сверка суммы по этажам с общей площадью, сверка
площади по документам и по факту, подстановка площади единственного этажа,
перенос материала наружных стен во внутренние, подсчёт количества этажей по
составу развёртки.

### Раздел 4. Справочники

Перечень справочников: название, количество значений, поля, которые из него
выбирают, сами значения.

### Раздел 5. Пул вопросов

Каждый вопрос:

* что именно неясно — одной фразой;
* ссылка на экран макета, где это видно;
* варианты с последствиями каждого, если варианты есть;
* на что влияет ответ.

## 3. Приложение: перечень полей

Отдельный файл-таблица. По каждому полю:

| Колонка | Содержание |
|---|---|
| Поле | название, как на экране |
| Вид объекта | объект оценки или вид объекта имущества |
| Где находится | номер и название блока карточки |
| Типы записи | в каких типах объекта оценки поле встречается |
| Тип значения | текст, число, целое, список, мультивыбор, отметка, текст многострочный |
| Единица | м², м, сом, годы |
| Справочник | название справочника и количество значений |
| Этап | на каком из пяти этапов поле заполняется |
| Заполняется дважды | да, если уточняется после осмотра |
| Источник значения | документ, техпаспорт, осмотр, расчёт |
| Описание | что означает величина |

В перечень входят только поля, несущие сведения об объекте. Не входят:
отметки управления таблицей, поля поиска, кнопки, служебные переключатели
отображения.

## 4. Требования к тексту

* Действующее лицо — пользователь. «Оценщик» — только про роль оценки.
* Слова предметной области: объект оценки, объект имущества, ЕНИ,
  правоустанавливающий документ, техпаспорт, осмотр, износ.
* Не употребляются: названия файлов и модулей, технические ключи полей,
  термины разметки.
* Единица измерения указывается везде, где величина числовая.
* Причина решения — одной фразой рядом с решением.
* Без смайлов и значков.
* Нет догадок: неизвестное идёт в пул вопросов, а не в текст.

## 5. Форма

* Документ — .docx: титул, оглавление, разделы, главы, сквозная нумерация.
* Приложение — .xlsx: закреплённая шапка, автофильтр.
* Сборка — скриптом в `tools/docs/`.
* Хранение локальное.
