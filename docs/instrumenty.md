# Инструменты проверки проекта

Макет живёт без сборщика: браузер грузит `app/main.js`, дальше ES-модули
подтягивают друг друга. Это удобно для правок, но у такого устройства есть
цена — **ошибка в коде видна только на том экране, где этот код выполняется**.
Забытый импорт, опечатка в имени функции, дубль ключа в объекте молчат до тех
пор, пока кто-нибудь не откроет нужную карточку.

Поэтому проверок два рода: те, что смотрят на живой экран, и те, что читают сам
код. Первые были давно, вторые заведены 14.09.2026.

## Что проверяет живой экран

| Чем | Команда | Что смотрит |
|---|---|---|
| Сценарии в браузере | `python tools/checks/run.py --changed` | 29 сценариев, около 2000 проверок: адрес и ЕНИ, архив, документы, просмотрщик, развёртка, перетаскивание, справочники, узкие экраны, сохранение и лог |
| Снимки экранов | `python tools/visual-parity/report.py --route "#/oc/civil/oc-cv-1" --oc civil --name floors` | Раскладывает снимки по `docs/screens/<коммит>/…` для отчёта |
| Playwright CLI | `npm run codegen` | Записывает сценарий кликами по макету — готовый код вместо ручного набора |
| Playwright CLI | `npm run trace -- trace.zip` | Разбирает запись прогона по шагам: состояние страницы до и после каждого действия |

Полный прогон `run.py` без аргументов — **только по просьбе пользователя**
(правило 11.09.2026): он занимает минуты.

## Что проверяет сам код

Эти четыре команды работают за секунды, без браузера, по всему проекту сразу.

| Чем | Команда | Что ловит |
|---|---|---|
| ESLint | `npm run lint` | `… is not defined`, дубли ключей в объектах, недостижимый код, мёртвые импорты |
| Stylelint | `npm run lint:css` | дубли селекторов и свойств — то, из-за чего правило ниже по файлу молча перебивает правило выше |
| dependency-cruiser | `npm run lint:arch` | изоляция модулей, «ядро не знает типов ОЦ», настоящие круговые зависимости |
| knip | `npm run dead` | файлы, которые никто не подключает, и экспорты, которые никто не импортирует |
| jscpd | `npm run clones` | объём повторяющегося кода — мера расхождения между копиями карточек |

Всё вместе — `npm run lint:all`.

### Архитектурные правила — теперь их проверяет машина

`.dependency-cruiser.cjs` повторяет то, что записано словами в CLAUDE.md:

* `modules/*` не импортирует `modules/*` — кроме карточки участка
  (`land-plot/oi/land/`), карточки квартиры (`apartment/oi/apartment/`) и
  словарей участка (`land-plot/data/landDicts.js`): это общие части, одни на
  весь проект;
* `kernel`, `shell`, `pages` не знают ни одного типа ОЦ — единственная дверь
  наружу — `kernel/registry.js`;
* круговых зависимостей нет. Циклы, проходящие через `registry.js`, не в счёт:
  реестр подгружает модули лениво, и в рантайме цикла не возникает.

Картинку этих связей рисует сам инструмент:

```
npm run graph            # docs/arhitektura.mmd — схема mermaid
```

Раньше такие схемы рисовались руками и устаревали на следующий день.

### Мера дублирования

`npm run clones` меряет то, с чем мы живём сознательно: карточка строения — пять
копий, карточка квартиры — две. Сейчас это **50% повторяющихся строк**; пары
вроде `apartment/oi/building/ctrl.js` ↔ `civil/oi/building/ctrl.js` совпадают на
620 строк. Число нужно не ради красоты: оно показывает, сколько правок
приходится разносить руками, и растёт, когда копии расходятся.

## Что эти проверки нашли при заведении (14.09.2026)

* `docsTab is not defined` в карточке ОЦ жилого здания — мёртвая ветка вкладки,
  которой в модуле нет; переход на неё уронил бы карточку;
* дубль ключа `auxBuildings` в подписях лога — во всех пяти модулях, вторая
  подпись молча затирала первую;
* четыре нарушения правила изоляции модулей (`data/dictExport.js` →
  `land-plot/data/landDicts.js`), не описанные ни в одном исключении;
* 188 неиспользуемых переменных и импортов, 416 лишних экспортов, один
  неиспользуемый файл;
* 80 дублей селекторов в CSS.

## Что дальше — заготовки на будущее

Не сделано, но лежит в этом же направлении:

1. **Визуальная регрессия.** `@playwright/test` умеет `toHaveScreenshot`:
   эталон хранится в репозитории, любое изменение пикселей показывается как
   diff. Заменит ручное разглядывание снимков в `docs/screens/`.
2. **Доступность.** `@axe-core/playwright` (уже установлен) прогоняет правила
   WCAG по живой странице: контраст, подписи полей, доступность с клавиатуры.
   Ложится на §8 чек-листа приёмки.
3. **Покрытие.** Playwright умеет снимать покрытие JS через CDP — станет видно,
   какие части макета ни один сценарий не открывает.
4. **Прогон перед коммитом.** Хук, который запускает три быстрые проверки кода
   и не даёт закоммитить очевидно сломанное.

## Установка на новой машине

```
npm ci                 # инструменты проверки
python -m pip install playwright && python -m playwright install chromium
```

`node_modules/` в репозиторий не попадает.
