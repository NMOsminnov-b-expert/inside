# «Осмотр» — техническое задание

Приложение для осмотра имущества: оборудования по описям, недвижимости и транспорта. Объект
осмотра — папка с разделами; у каждого предмета, литера, помещения и ТС — своя папка, в неё
снимает своя камера приложения. Документы объекта (PDF, перечни Excel) смотрятся прямо в
приложении, параметры литера и ТС заполняются формой, результат уходит отчётом Excel и архивом.
Работает без интернета.

Цель — **максимально быстрый и удобный осмотр**, без лишнего: ни одного вопроса там, где можно
решить самим (автор, 08.10.2026: «мы просто делаем снимки, перейдя в папку в приложении. Не грузи
пользователя деталями»).

Платформы: **Android** — основная (APK, Android 8+); **iPhone** — то же приложение из общего
кода (`docs/iphone.md`); **браузер (PWA)** — `docs/pwa.md`. Различия — раздел 9.

Документ описывает версию 3.17 (30.10.2026). Каждый сценарий проверен тестами и путями матрицы
устройства — реестр `tools/matrix/scenarios.py` (столбец «Реестр» ниже); расхождение ТЗ и
реестра — ошибка ТЗ.

## 1. Устройство

```
Осмотры/                                   корень памяти телефона (виден по USB)
├── <Объект>/                              «Новый объект», сообщение о выезде, лист сводной
│   ├── Объект.txt                         сведения: учреждение, адрес, код
│   ├── Контакты.xlsx
│   ├── Недвижимое/
│   │   ├── Документы/                     техпаспорт и прочие документы недвижимости — не к литеру
│   │   ├── Земельный участок/             снимки; Земельный_участок.json — параметры
│   │   ├── Литер А/                       Литер_А.json — параметры (строение или квартира)
│   │   │   ├── Фасад/
│   │   │   └── Внутренние помещения/
│   │   └── Найденное …/                   то, чего нет в документах, — так же
│   ├── Движимое/
│   │   └── 01KG 777 ABC/                  ТС по госномеру: снимки, PDF, 01KG_777_ABC.json
│   ├── Документы/                         PDF и перечни Excel
│   ├── Механизмы и оборудование/
│   │   └── <опись>/                       опись Excel, отчёт, журнал, папки предметов
│   └── <своя категория>/                  «Новая категория» в корне объекта
└── Осмотрено ранее (старая версия)/       всё, что лежало до объектов, — один раз при обновлении
Загрузки/Осмотр/                           собранные архивы
```

Корень объекта — не место снимкам: в нём «Новая категория» вместо «Снимать».

### Человеческий фактор

| Ошибка | Что делает приложение |
|---|---|
| Удалил не то (снимки или папку) | внизу «Удалено: … · Вернуть»; папку перед удалением — подтвердить |
| Снял не в ту папку | выбрать → «Переместить» |
| Создал папку не на том уровне | «Переместить папку» (в саму себя и во вложенную — нельзя; занято имя — «Имя (2)») |
| Прислали тот же документ второй раз | не копируется, сказано «уже лежит» |
| Снимок в «Документы» | не ложится: «Здесь — только PDF и Excel» |
| PDF под паролем или битый | так и сказано, «Открыть в другом приложении» |
| «0.6↗»: ушёл из штатной камеры «Домой», снимал своё | забирается только снятое этой камерой за 2 часа от начала захода; снимки экрана и мессенджеров — никогда |
| Приложение выгрузилось, пока открыта камера | кадры уже в папке (своя камера пишет сразу); «0.6↗» — заход хранится на диске |
| Папки поменяли с компьютера | папка перечитывается; журнал описи показывает правки мимо приложения |
| Имя с «/», «:» и т. п. | недопустимые знаки заменяются |
| Села батарея сразу после записи | запись во временный файл и подмена — файл либо прежний, либо новый целиком |

## 3. Требования к скорости (проверяемые)

- Холодный запуск — ≤ 1 с; камера открывается ≤ 2 с (одна задняя камера на старте).
- Снимок — в момент нажатия; кадры дописываются в фоне, очереди не сталкиваются.
- Сетка читает миниатюры (≈ 384 px), сделанные в фоне; 2000+ снимков листаются без пропуска кадров.
- PDF: документ открывается один раз, страницы держатся в памяти (до 8), увеличенное —
  перерисовка только видимой части; одна картинка — не больше 16 Мп.
- Добавление документа — потоком: скан на сотни мегабайт не поднимается в память.

## 4. Хранение

- **Папка в корне памяти телефона: `Осмотры/…`** — по USB всё уже разложено; папка в
  приложении = настоящий каталог, без базы данных.
- Каждый новый файл регистрируется в системе (MediaScanner): иначе по USB его не видно.
- Имена снимков: `<папка>_<ГГГГММДД_ЧЧММСС>_<NNN>.jpg`; голос — `<папка>_голос_<…>.m4a`.
- Параметры литера, участка и ТС — один JSON на папку (`Литер_А.json`), с отметкой «Осмотр
  закончен» и перенесённым с участка; прежние «Параметры осмотра.json» и «Комментарий.txt»
  вливаются сами.
- Опись: копия файла «Опись — <имя>.xlsx», отчёт «Осмотр — <имя>.xlsx», журнал `Журнал.jsonl`,
  отметки — `Нерабочие.txt`, `Требуется ремонт.txt`, `Осмотрено ранее.txt`.
- Архивы — в `Загрузки/Осмотр`, ZIP потоком; «по частям» — под предел мессенджера.
- Миниатюры, журнал работы и отчёты о сбоях — во внутренней памяти приложения.

## 5. Съёмка

- **Своя камера** (CameraX): кадр сразу ложится в папку, серия без выхода, «Снято: N»,
  миниатюра последнего; формат 4:3 (по умолчанию) или 16:9, сетка, вспышка; ступени 0.6 / 1× /
  телевик (что есть у телефона); фокус касанием, яркость протяжкой, ручные выдержка, ISO и
  фокус, «ярче в темноте»; видео — в папку предмета (со звуком, если разрешён микрофон).
- **«Документ»** — сканер документов Google: края листа, выравнивание, несколько страниц;
  страницы — снимками в папку.
- **«0.6↗»** — где широкий угол спрятан от приложений (Xiaomi): штатная камера целиком; по
  возвращении снятое ею за заход переносится из DCIM в папку предмета.
- **«Из галереи»** — системный выбор фото, только отмеченные, копиями.
- **Присланные фото** («Поделиться» → «Осмотр») — окно «Куда положить»: предметы описей, дерево, новая папка.

## 6. Документы и PDF

- PDF и перечни Excel лежат файлами под своими именами: общие — в «Документах» объекта, недвижимости —
  в «Недвижимое/Документы», ТС — в папке госномера.
- Просмотр PDF — своей лентой (Android, `PdfRenderer`): см. С13а. Поиск по тексту PDF —
  «Открыть в другом приложении».
- Перечень Excel — любой .xlsx/.xls, кроме служебных; шапка угадывается, поиск по всем ячейкам.

## 7. Личные данные и сеть

- Своего сервера, учётной записи, входа нет; приложение в интернет не обращается. Разрешение
  «Интернет» в APK — от модуля Google для режима «Документ» (документ обрабатывается на
  телефоне; Google получает обезличенные метрики работы сканера).
- Доступ ко всем файлам — ради `Осмотры` и `Загрузки/Осмотр`; остальная память не просматривается.
- Галерея — только выбранное в системном окне; исключение — «0.6↗» (раздел 5).
- Контакт — только выбранный в системном окне; телефонная книга не читается.
- Журнал работы — без имён описей и папок, текста поиска, комментариев, контактов; почта и
  телефоны вычищаются; уходит только по «Отправить».
- Подробно для людей — руководство пользователя (`docs/guide` в ветке версии «по механизмам»).

## 8. Доступность

- Всё, что нажимается или куда вводят текст, — со словами для TalkBack (проверка —
  `UiAccessibilityTest` по узлам доступности Android, а не по дереву Compose).
- Плавающие кнопки и поля, чья подсказка закрыта самим полем, подписываются явно (`voiceLabel`).

## 10. Практики, на которые опирается решение

- **Без базы данных**: файловая система — единственный источник правды.
- **Своя камера** вместо штатной (автор, 19.10.2026: «камера наша», «без переоткрывания
  камеры»): кадр сразу в папке, никаких переносов из DCIM; штатная — только для «0.6↗».
- **Фоновые миниатюры**: `inSampleSize`, поворот по EXIF, однопоточный исполнитель.
- **Compose**: ленивые сетки с ключами по пути, Coil с явным размером; тяжёлое — в фоне.
- **PDF**: один открытый документ на приложение и строгая очередь обращений (`PdfRenderer` —
  одна страница за раз); увеличенное — кусками видимого, а не страницей целиком.
- **Удаление** — с подтверждением и «Вернуть».

## 12. Разбор блоков описи (08.10.2026)

Люди — не самые квалифицированные: ни одного вопроса там, где можно решить самим; на каждое
долгое действие — шкала; на каждую ошибку — понятная причина.

| Блок | Что нужно человеку | Сделано |
|---|---|---|
| Загрузка описи | бросить файл(ы) и работать | «Новая опись» — сразу несколько файлов, каждый своей описью; имя — из файла, мусорное имя мессенджера — заголовком из книги; .xls / не Excel / нет списка — понятной причиной; шкала «Читаем лист… — 45 %» |
| Подбор столбцов | не думать о столбцах | словарь RU/EN/KY с опечатками, шапка в несколько этажей, сверка данными, таблица без шапки, итоги/повторы шапки/«1 2 3…»/разделы пропускаются; набор из 22 самых кривых шаблонов — `tools/make_templates.py`, тесты `TemplatesTest` |
| Проверка | — | не нужна (автор: «описи на 5000 частенько… вручную никто сверять не будет») |
| Поиск предмета | найти по бирке или по словам | инвентарник без разделителей; слова в любом порядке, с опечатками |
| Предмета нет в описи | снять и не потерять | «Не найдено — создать папку»; в отчёте — лист «Нет в описи» |
| Что с предметом не так | записать | комментарий папки; «нерабочее» или «требуется ремонт»; в отчёте — столбцы |
