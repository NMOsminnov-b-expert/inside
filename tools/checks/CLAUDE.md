# Автопроверки — как гонять и как писать

Подгружается при работе в `tools/checks/`. Правила — записи графа группы
«Проверки» (`graph.py rules`); здесь — подробности (перенесено из
корневого CLAUDE.md 30.10.2026). Устройство — `README.md` рядом.

## Прогон

    python tools/checks/run.py ЕНИ адрес       # обычный ход: только по теме правки
    python tools/checks/run.py --changed       # по изменённым файлам (осторожный отбор)
    python tools/checks/run.py --show          # с открытым браузером
    python tools/checks/run.py                 # ВСЁ — только по просьбе пользователя

* Полный прогон — только по прямой просьбе пользователя (11.09.2026). По
  своей инициативе — названные сценарии или `--changed`.
* `--changed` берёт изменённые файлы из git и оставляет сценарии, чьи
  `TOUCHES` называют эти пути. Правка каркаса или файл, не названный ни в
  одном сценарии, ведёт к полному прогону, а не к пропуску.
* Щадяще (28.10.2026, «Проц задыхается»): по умолчанию два потока и
  пониженный приоритет (`harness.py`); матрицы — одним заходом в конце задачи.
* Ошибка в консоли браузера — провал автоматически.
* В отчёте — честно, что гонялось: «точечно, сценарии такие-то».

## Новая проверка

* Файл `tools/checks/check_<область>.py` с `NAME`, `TOUCHES` и `run(t)`;
  `run.py` подхватит сам. В шапке — какой дефект ловит.
* Ждать по факту (`t.wait_for`, `t.wait_until`), а не отсчётом времени.
* Покрываются ВСЕ варианты (23.10.2026): каждый вид объекта, ветка
  поведения, место показа; нет данных — создать демо-запись или собрать в
  проверке. «Не покрыто» — только с неустранимой причиной.
