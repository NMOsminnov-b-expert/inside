# Проверки макета

Сценарии в браузере, которые ловят уже случавшиеся дефекты. Запуск:

```
python tools/checks/run.py                 # все проверки
python tools/checks/run.py архив ЕНИ       # только названные (по части имени)
python tools/checks/run.py --show          # с открытым браузером, чтобы смотреть
```

Нужен `playwright` (тот же, что у `tools/visual-parity`). Сервер и браузер
поднимаются сами, один раз на весь прогон; в конце печатается сводка и код
возврата `1`, если что-то провалилось.

## Что где проверяется

| Файл | Область |
|---|---|
| `check_basics.py` | экраны всех модулей открываются, правки сохраняются, лог действий пишется, заголовок вкладки различает экраны, слушатели не копятся |
| `check_eni.py` | код ЕНИ: маска, длина 18 цифр, запрет сохранения с неверным кодом |
| `check_flags.py` | один значок ML вместо двух, цвет особенностей, сортировка по флажкам вглубь списка, выгрузка со столбцом «Теги» |
| `check_archive.py` | документ уходит в архив и возвращается, поиск и фильтры архива, права доступа |
| `check_layout.py` | ничего не выходит за окно на 1600/1366/1152/1024, значения в полях и шапке не обрезаны, поэтажная развёртка помещается |

## Как добавить проверку

Новый файл `check_<область>.py` рядом; в нём `NAME = 'что проверяем'` и функция
`run(t)`. Объект `t` даёт:

- `t.open(маршрут)` — перейти и дождаться отрисовки;
- `t.page` — страница Playwright;
- `t.ck(условие, 'что сломано, если условие ложно')` — проверка;
- `t.text()` — текст страницы.

`run.py` подхватит файл сам. Ошибки в консоли браузера считаются провалом
автоматически — отдельно проверять их не нужно.

В шапке файла стоит написать, какой именно дефект сценарий ловит: через полгода
это единственный способ понять, можно ли проверку менять.
