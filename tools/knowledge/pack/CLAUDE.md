# Граф знаний

Здесь — граф знаний проекта E•state (макет системы оценки имущества) с его
обвязкой: утилиты поиска, программа «Граф проекта», индекс CodeGraph и хук
обновления индекса. Кода макета здесь нет — только знания. Рядом — второй
граф, база категорий механизмов и оборудования по описям («каталог»).

Пакет собирается в репозитории макета командой
`python tools/knowledge/export_pack.py`; там же — первоисточник записей.

# Данные наружу не уходят

Сведения графа — секретные. Не публиковать записи, выдержки, схемы и снимки —
ни в артефакты, ни в облачные сервисы, ни в чужие репозитории. В поисковые
запросы — только общие слова («как оформляют перечень полей по ГОСТ»), без
слов из записей. Исключения: при опознании позиций описей в поиск можно
отправлять **только марку и модель** («Samsung HS40») — без наименований
учреждений, цен, инвентарных номеров и адресов.

`git push` — только по прямой просьбе человека. Заметки и логи в `.claude/` не
вести: их место — записи графа, журнал — история коммитов.

# Как работать с графом

1. В начале работы — оглавление и действующие правила:

       python tools/knowledge/graph.py toc
       python tools/knowledge/graph.py rules

2. Сначала искать в графе, потом спрашивать человека:

       codegraph query "<слово или фраза>"       # по словам, по индексу
       python tools/knowledge/graph.py find <слова>
       python tools/knowledge/graph.py tag <метка>
       python tools/knowledge/graph.py --all find <слова>   # по всем графам

   Графы мультиграфа — `graph.py graphs`; каталог — `graph.py --project katalog find …`.
   Ссылаясь, называть граф: «граф katalog, запись <ID>».

3. Чего нет в графе — спрашивать человека, не додумывать.
4. Ответ человека сразу заносить в граф: `python tools/knowledge/graph.py new
   <папка> <заголовок>` или пункт в существующую запись — с датой, поводом и
   цитатой. После — `python tools/knowledge/graph.py check`, затем коммит; в
   описании коммита — что и почему поменялось в знаниях.

Устройство записи — `knowledge/README.md`: одна запись — один файл
`knowledge/<папка>/<id>.py` с константами `ID`, `KIND`, `TITLE`, `TAGS`,
`STATUS`, `DATE`, `SOURCE`, `POINTS`, `LINKS`. Файл не исполняется — читается
разбором.

Поиска по смыслу (semsearch) в пакете нет: хук и программа его пропускают.

# Скорость на больших перечнях

`graph.py find` разбирает все записи заново — 1–2 секунды на запрос. Сверять
тысячи строк описи запросом на строку нельзя: писать скрипт, который один раз
читает записи (`tools/knowledge/graph.py`, функция `load_all`) и проходит весь
перечень за один прогон; человеку и Claude — только то, что не сопоставилось.
