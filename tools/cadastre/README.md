# Адрес из Кадастра по коду ЕНИ

В форме объекта оценки, в блоке 02 «Местоположение», есть строка «Портал
Кадастра» с кнопкой **Заполнить адрес**: по коду ЕНИ из портала
[cadastre.kg](https://cadastre.kg/svc-portal/map/main.do) приходят область,
район, населённый пункт, улица и дом.

Подстановка идёт **только по кнопке**. Автоматическая, по вводу кода, не давала
убрать адрес вовсе: сотрёшь поля, тронешь код — и они заполнены снова.

## Зачем прокси

Портал отвечает обычным HTML-фрагментом и **не отдаёт** заголовок
`Access-Control-Allow-Origin`. Браузер такой ответ читать не даст: запрос уйдёт,
а результат заблокируется. Прежний скрипт на VBA этого ограничения не знал —
`MSXML2.ServerXMLHTTP` не браузер, и CORS ему не писан.

Прокси делает ровно один шаг: принимает код, ходит на портал сам и возвращает
разобранный адрес с разрешающим заголовком.

## Запуск

```
python tools/cadastre/proxy.py            # 127.0.0.1:8787
python tools/cadastre/proxy.py --port 9000
python tools/cadastre/proxy.py --check 7100600330016   # разовый запрос
```

Проверка:

```
curl "http://127.0.0.1:8787/eni?code=7100600330016"
{"eni": "7100600330016", "address": "обл. Чуй, г. Токмок, ул. Гагарина, д. 82"}
```

Прокси нужно **запустить и оставить работать** — это сервер, а не разовая
команда. `--check` только проверяет связь с порталом и завершается; интерфейсу
он не поможет.

## Два обхода и почему такой порядок

Макет спрашивает сначала свой прокси, и лишь потом прокси Live Server
(`liveServer.settings.proxy` в `.vscode/settings.json`).

Свой прокси, когда поднят, отвечает сразу и разбирает ответ портала сам; когда
не поднят — браузер отказывает в соединении мгновенно, и мы ничего не теряем.
Обратный порядок обходился дорого: прокси Live Server отвечает то 405 (не
включён — настройка применяется при СТАРТЕ, уже запущенный её не видит), то 500
(не справляется с https-адресом портала), то молчит до таймаута, и рабочий путь
ждал его по шесть секунд.

## Как это ведёт себя в форме

* заполняются **все** поля местоположения, и пустые, и заполненные: кнопку нажал
  человек, значит ждёт адрес из Кадастра, а не смесь со своим;
* результат и причина отказа показываются в самой строке — всплывающее
  сообщение исчезает раньше, чем длинный текст дочитают;
* без кода ЕНИ кнопка выключена: незачем звать портал впустую;
* ответы на уже спрошенные коды берутся из памяти вкладки;
* каждое нажатие пишет в консоль строку `[Кадастр] <код>: свой прокси — …;
  Live Server — …`. Если «не работает» — смотреть надо туда: там сказано, какой
  обход и чем именно отказал.

## ДЛЯ СЕРВЕРНОЙ ВЕРСИИ

Прокси — подпорка макета: он живёт рядом с Live Server и работает только у того,
кто его запустил. На сервере запрос к Кадастру делает бэкенд по своему API, а
фронт зовёт его; там же уместен кэш ответов — портал отвечает не мгновенно, а
один и тот же код спрашивают многократно.

## Координаты участка (13.10.2026)

Тот же прокси пропускает к карте портала: `/portal/<путь>` →
`https://cadastre.kg/svc-portal/map/<путь>` (GET и POST, с сессией портала и
разрешающим заголовком). Прокси Live Server делает то же по `/cadastre/<путь>`.
Разбор ответов — один на оба обхода, в `app/kernel/cadastreGeo.js`.

* **Рамка по ЕНИ** — `getFeatureExtent.do?propCode=<13 цифр>` →
  `{"extent":{minx,miny,maxx,maxy}}` в широте и долготе; нет участка — `null`.
* **Контур** — WFS картосервера: `POST proxy.do?http://localhost/o2map/services/wfs`,
  `typename=ENI_AREA`, отбор `PROPCODE` с дефисами (`1-04-17-0014-0095`),
  `srsname=EPSG:4326`, `bbox` — в EPSG:3857 (без него ответ пустой).
* **Адрес → ЕНИ** — справочник `searchAddr.do?mode=region|ao|village|street`
  (у Бишкека и Оша улицы сразу после области, у города областного значения —
  сразу после «района»-города), затем `searchAddrResult.do` с
  `searchCondition=ADDR`.

В карточке ОЦ — строка «Координаты участка» в блоке «Местоположение» (рамка
целиком, контур, центр — в поле GPS, карта участка); в реестре — «Координаты
из Кадастра» по отмеченным. Подробности и решения — запись графа
`geokodirovanie-koordinat-po-adresam-ili-eni`.

    curl "http://127.0.0.1:8787/portal/getFeatureExtent.do?propCode=7100600330016"
