# Граф проекта

Всё, что проект знает о себе и о предметной области: решения, правила,
открытые вопросы, задачи, практики, источники, понятия, поля, заметки о
модулях кода. Поиск — CodeGraph; журнал изменений — история коммитов.

## Устройство

Одна запись — один файл `knowledge/<папка>/<id>.py`. Имя файла латиницей
(дефисы ID заменены подчёркиванием): кириллица в путях по-разному
отображается в терминалах и `git status`.

| Папка | Вид записи |
|---|---|
| `decisions/` | решение — что решили, кто, когда и почему |
| `rules/` | правило работы — действует до отмены |
| `questions/` | вопрос — открытый или закрытый с ответом |
| `tasks/` | задача — в работе, отложена или закрыта |
| `practices/` | практика — найденное решение со ссылкой на источник |
| `sources/` | источник — ТЗ, методология, документ, совещание |
| `tools/` | утилита — скрипт, программа, как ей пользоваться |
| `code/` | модуль кода — назначение и неочевидное устройство |
| `terms/` | понятие с пояснениями (ссылка на запись реестра) |
| `concepts/` | реестр: понятие, снятое с экранов макета |
| `fields/` | реестр: поле, снятое с экранов макета |
| `project/` | проект целиком |

## Почему запись — Python-файл

CodeGraph ищет текст только в значениях констант исходного кода: у YAML он
читает одни ключи (значения там бывают паролями), Markdown не читает вовсе —
проверено 28.09.2026. Поэтому запись — модуль с константами, и
`codegraph query "<фраза>"` находит её по заголовку, метке или пункту.

Файл — данные, не код: он не исполняется, `tools/knowledge/graph.py` читает
его разбором (`ast`).

## Состав записи

| Константа | Что содержит |
|---|---|
| `ID` | устойчивый идентификатор, по нему ссылаются связи |
| `KIND` | вид записи — по папке |
| `TITLE` | заголовок (у понятий и полей реестра — `TERM`) |
| `TAGS` | метки: вид, модуль (`civil`, `apartment`…), тема (`методология`, `разметка`…), особые (`под-вопросом`, `восстановлено`, `работа-с-claude`) |
| `STATUS` | `действует`, `отменено`, `открыт`, `закрыт`, `отложено`, `актуально`; у реестра — `черновик`, `подтверждён` |
| `DATE` | дата решения или первого упоминания |
| `SOURCE` | откуда: сообщение пользователя, документ, совещание, макет |
| `OLD_NAME` | имя узла в прежнем графе на сервере памяти — чтобы найти запись по старой ссылке |
| `POINTS` | пункты: суть, повод, цитаты, даты |
| `LINKS` | связи: `{'тип': …, 'куда': ID, 'папка': …}` |

У понятий и полей реестра — свои части: `TERM`, `SYNONYMS`, `DEFINITION`,
`VALUE_TYPE`, `UNIT`, `REQUIRED_IN`, `STAGE`, `OCCURS` и др.

## Команды

    codegraph query "<фраза>"                          найти запись (RAG)
    python tools/knowledge/graph.py rules              действующие правила коротко
    python tools/knowledge/graph.py find <слова>       запасной поиск по тексту
    python tools/knowledge/graph.py tag <метка>        записи с меткой
    python tools/knowledge/graph.py new <папка> <заголовок>   заготовка записи
    python tools/knowledge/graph.py check [--full]     ошибки (валят проверку) и замечания к наполнению
    python tools/knowledge/graph.py stats              сколько чего; числа качества
    python tools/knowledge/graph.py suggest [<id>]     кандидаты связей (общие соседи, сходство текста)
    python tools/knowledge/structure_review.py build   книга docs/graf-struktura.xlsx на согласование
    python tools/knowledge/structure_review.py apply   применить согласованную книгу
    python tools/knowledge/view_graph.py --open        граф картинкой, 2D и 3D (local-docs/graf-proekta.html)
    codegraph sync                                     обновить индекс после правок

Реестр понятий и полей:

    python tools/knowledge/migrate_from_mockup.py      пересобрать из макета
    python tools/knowledge/check_registry.py           сверить реестр с макетом

## Правила ведения

* Ответ человека заносится сразу, в том же разговоре: дата, повод, цитата.
* Изменение записи — в том же коммите, что и правка, к которой оно
  относится; в описании коммита — что и почему поменялось в знаниях. Это и
  есть журнал графа: `git log -- knowledge/`.
* Запись не удаляется, если решение отменено: `STATUS = 'отменено'` и пункт с
  датой и причиной.
* Знания не ведутся нигде кроме графа — ни в `.claude/`, ни в заметках
  помощника (решение 28.09.2026).

## Реестр понятий и полей

Записи `concepts/` и `fields/` сняты с работающих экранов макета, а не из
кода: скрипт открывает карточки и выписывает то, что на них видно, поэтому у
каждой записи указан экран, на котором её можно проверить. Начальное
наполнение — `STATUS = 'черновик'`: определения не выдуманы и оставлены
пустыми. Что сделать с записью: написать определение своими словами, указать
этап заполнения, проверить синонимы, сменить статус на `подтверждён`.

Термин, помеченный звёздочкой на экране, обязателен — звёздочка в название
не входит, она записывается в `REQUIRED_IN` с указанием места. Тип объекта
оценки и вид объекта имущества — разные понятия, даже когда называются
одинаково. Одно название поля — одна запись со списком мест, где оно
встречается.

## Прежний граф

До 28.09.2026 знания жили в графе на сервере памяти MCP с файлами лога в
`.claude/knowledge-graph/`. Он снят: логи в `.claude` — возможная утечка, а
пересборка кэша из логов стирала записанное через сервер. Всё содержимое
перенесено сюда (`tools/knowledge/migrate_from_graph.py`), включая записи,
стёртые пересборкой и восстановленные из стенограммы (метка
`восстановлено`), и заметки помощника о правилах работы (метка
`работа-с-claude`).
